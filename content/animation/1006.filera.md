## A visual workflow for repetitive work

Renaming one file is easy. Renaming a few thousand files consistently—and being certain they will all come out right—is a different problem.

I built Filera to make that work fast, visual, and approachable. Instead of requiring a script or a dense regular expression, Filera lets you assemble a pipeline of straightforward tasks and filters. Load individual files or an entire folder tree, arrange the operations in the order they should run, and watch every proposed filename update immediately.

The interface is organized around that feedback loop. The left panel keeps the original and proposed names side by side, along with search, sorting, selection, and file statistics. The right panel holds the transformation pipeline. Find and replace, numbered sequences, custom text, case conversion, dates, and times can be stacked in any order. Filters narrow the operation by name, extension, date, or size without removing files from view.

## Preview first, commit second

Batch tools need to feel powerful without feeling dangerous. Filera does not touch the filesystem while a pipeline is being designed. Every adjustment is reflected in the preview, filtered files are visibly dimmed, and potential duplicate names are resolved before the operation runs.

Once the results look right, files can be renamed in place, copied to another directory, or moved and renamed in a single operation. Drag-and-drop and recursive folder loading make it practical to bring in large collections quickly, while familiar Shift and Command/Control selection patterns provide more precise control when only part of a batch needs attention.

## Rust where it matters

Filera is a Tauri application with a Vue 3 and TypeScript interface backed by a Rust processing engine. The frontend owns the interactive pipeline and preview experience; Tauri commands hand file operations, metadata, sorting, filtering, and rename execution to Rust.

Keeping the filesystem logic in Rust made it possible to process thousands of files while maintaining a responsive interface and a clear boundary between presentation and destructive operations. The same architecture ships across macOS, Windows, and Linux without maintaining separate applications for each platform.

The release workflow is part of the product too. GitHub Actions packages Windows and Linux builds, produces a universal macOS binary for Apple Silicon and Intel, handles signing and notarization, and publishes additional NixOS support.

## Documentation is part of the application

I built [filera.app](https://filera.app) as the companion documentation and download experience. The static Nuxt Content site covers installation, the interface, every task and filter, output modes, and safe batch-renaming practices. Platform-specific download cards resolve against the latest GitHub release, keeping the path from documentation to installation short.
